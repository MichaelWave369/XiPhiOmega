# XPO-006 v1 — scoped authority and independent replay

Status: SYNTHETIC / local-fixture-permit only. A trusted host constructs a single in-memory journal gate. No real device, shell, arbitrary code, network, model or external state execution is available. No upstream code reused.

## Permit wire contract

Canonical compact ASCII JSON array [body, signature], maximum 2,048 bytes. Body is the ordered eleven-field array:
1. xpo6.permit.v1
2. xpo6.synthetic-journal (fixed audience)
3. gate ID
4. issuer key ID
5. nonce (32 lowercase hex characters)
6. expected journal revision (integer 0..35)
7. expected journal tip (64 lowercase hex characters)
8. exchange.synthetic (only supported operation)
9. weight (integer 0..12)
10. issued Unix seconds
11. expires Unix seconds

IDs match ASCII [a-z][a-z0-9.-]{0,63}. Time values are nonnegative safe integers; issued <= host clock < expires and duration at most 60 seconds. Signature is 128 lowercase hex characters, Ed25519 over the canonical ASCII JSON body. No alternate key, clock, payload or operation supplied by client. Host pins one public Ed25519 KeyObject, gate ID, issuer ID, verified initial journal and clock. No signing key inside gate. Test keys ephemeral; never use fixture signing conventions as production key management.

## Execution

Validate shape, canonical bytes, fixed scope, signature, trusted host time, exact revision and tip. The XPO-005 operation ID is permit.<nonce>. Append verifies journal, rejects duplicate operation ID, recomputes mathematical state and enforces 36-event capacity. Only after successful replay is the internal journal replaced. Refusals leave snapshot unchanged. Synchronous single-instance reference only, not a durable database transaction. Receipt describes local gate admission, not cryptographic attestation of actual execution. Journal classification remains synthetic / authority none. An independent Python XPO-005 verifier recomputes the final journal and tip.

## Limits and threat model

The host is trusted; its public key and clock are not client-controlled. No human identity, revocation, key rotation, distributed consensus, durable nonce store, rollback-resistant clock, cross-process concurrency, crash recovery, remote trust or hardware attestation. Gate ID is a logical scope, not proof of a unique deployed instance. Recreating the gate with an old journal and same scope can accept the original unexpired permit again; the test explicitly demonstrates this limitation. Do not deploy as a production access control service. A valid signature does not prove the mathematical result; replay does not prove authority. No signed receipt or native Xi/Phi/Omega compatibility claim.
