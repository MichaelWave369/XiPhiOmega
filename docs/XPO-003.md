# XPO-003 v1 — recursive address and identity

Status: SYNTHETIC / authority NONE. Original interchange experiment. No native upstream adapters.

## Address contract

Canonical ASCII address: xpo3/<namespace>/<space>/<segment>/... . Namespace follows XPO-002 ASCII label grammar (1–64 characters); space is state or relation. Each segment is exactly six ASCII decimal digits, zero-based 000000–020735. Depth is 1–36, an implementation budget rather than a mathematical limit. No root address: the parent of a depth-one address is null. A child appends a segment; a parent drops one. Leading zero segments are significant. State and relation spaces have equal cardinalities but different declared semantics; no automatic crosswalk, edge, causal relation or allocation follows from a valid address.

Ordinal is a four-field object {namespace,space,depth,index}, where index is the canonical unsigned decimal STRING (no leading zero except zero). N = sum of segment[i] * 20736^(depth-1-i). The inverse uses repeated exact integer division. Depth is mandatory; otherwise [0] and [0,0] collide. Reject invalid depth, out-of-range values and strings over 156 digits before big-integer conversion. BigInt in JS, int in Python; never JSON floating point.

Identity is a separate ASCII string xpo-id/<namespace>/<id>. The locator pairs identity and address, without proving allocation, uniqueness, ownership, authorization, relocation or existence. No registry is implemented. Rebinding in this pure example is not an authorized move. Namespace labels are not authenticated.

## Representation is not topology

For a single segment, four base-12 coordinates and a 192x108 raster are reversible representations. Raster x = index mod 192, y = floor(index/192). Segment 11 and 12 are adjacent raster pixels but differ on two base-12 axes. No graph adjacency or metric is inferred by either conversion. Relation addresses remain distinct from state addresses. These mappings do not imply physical dimensions or holographic compression.
