# XPO-009 v1 — integrated reproducible evidence

Status: SYNTHETIC reference demonstration. No upstream participation, native adapters, live external actions or production authority. The topology study remains a separate regression, not part of this two-pocket exchange.

## Run

Requirements Node 20+, Python 3.10+, OpenSSL 3 CLI available on trusted PATH. No npm or pip packages.

```sh
node scripts/demonstrate.mjs xpo9-output
python3 scripts/verify_evidence.py xpo9-output/trust.json xpo9-output/evidence.json
node tests/evidence-conformance.mjs
```

Output directory must be new. The demonstration generates an ephemeral Ed25519 keypair, deterministic genesis and 36-step weight schedule (1..11 repeating, last 12), Python-produced proposals, Node execution, full journal, and separate trust/evidence JSON. The private key never leaves the generating process. No secrets or generated evidence committed. Exact state evolution is reproducible; random keys, signatures and their bytes vary. Both files are generated by the demo for convenience; **a verifier must obtain trust.json from an independently trusted source for any meaningful trust claim.** Merely accepting the accompanying file proves self-consistency, not independent authorization.

## Evidence and trust

Evidence exact fields: schema xpo9.evidence.v1, classification synthetic, rows (each proposal hex, permit string, approval hex, response hex), journal (canonical full XPO-005 string). Trust exact fields: schema xpo9.trust.v1, gate, issuer, publicKey (Ed25519 SPKI PEM), genesis, weights, reviewTime. Trust pins expected schedule, genesis, gate, issuer and verification time (synthetic clock 1000 for demo). The new detached approval signs canonical ASCII JSON ["xpo9.approval.v1", SHA256(proposal bytes), SHA256(permit ASCII bytes)] using the same reviewer key, distinct domain from XPO-006 permit. It binds the exact reviewed proposal and permit; not a second independent signer. Existing gate still checks XPO-006 permit and XPO-008 proposal correspondence. Demo verifies detached approval before calling exchange; earlier gate API itself is unchanged and does not require XPO-009 approval.

Verifier separately receives the trust file and evidence file. Bounded input, duplicate JSON keys refused, exact Ed25519 SPKI algorithm prefix, canonical permit, pinned scope/time/nonce/revision/tip/weight. OpenSSL verifies both signatures for every row. Independent Python codec, semantics, address mapping and Fraction replay validate every history prefix and response. Report does not assert external execution. Full package requires exactly the independently expected number of transitions. Refuse corruption, wrong trust, truncated/reordered rows, changed claims and altered packets.

## Evidence scope

Signed approval is not signed execution attestation. Anyone with a legitimately signed proposal/permit can compute the deterministic expected result without executing the original gate. Verification proves matching signed inputs and mathematically consistent results relative to caller-supplied trust, not where/when an executor ran. No durable rollback protection, production key lifecycle, network or native adapter. Review time is a pinned fixture time, not proof of a real timestamp. Local trusted PATH and Python/OpenSSL binaries assumed. Independent implementation here means separate language and cryptographic interface, not a separate organization or necessarily distinct underlying crypto library (Node may use OpenSSL too). No general intelligence, biological or physical claim.
