# XPO-008 v1 — cross-runtime reference interoperability

Status: SYNTHETIC, local fixture only. No native Xi/Tessera, Phi/Altermath or Omega/Dewey integration, participation or endorsement. No network, external actions or upstream changes.

## Pipeline

Python XPO-002 encoder constructs a proposal with fixed XPO-003 identities and locations. Node decodes, validates exact fixture locations, translates the XPO-004 demo resource meaning into the target dialect and checks the weight is on the XPO-005 grid. An operator-controlled test signer independently compares the proposal with planned input, then issues an XPO-006 Ed25519 permit. The adapter checks permit nonce, revision, tip, operation and weight against the proposal. The existing gate independently checks signature, scope, time and journal admission, executes and returns the new history. Python independently decodes the result, verifies proposal digest, compares original journal prefix and exact new event, replays all mathematics, and checks final state and result bytes' decoded fields. The topology experiment XPO-007 remains an independent regression, not a mechanism used by this two-identity exchange.

## Wire contract

Proposal XPO-002 namespace xi.demo.v1, operation exchange.propose.v1. Eleven atoms in order: A identity, A location, B identity, B location, symbol, unit, status, canonical rational, revision decimal, prior tip, nonce. Fixed identities xpo-id/phi/pocket-a and pocket-b, locations xpo3/phi/state/000144/000000 and /000001 respectively. Only known resource values in [0,1] on increments 1/12 admitted. Source demo symbol ⊚, unit 1; target demo symbol ∴, unit 1. The semantic registry is synthetic.

Result namespace omega.demo.v1, operation exchange.result.v1. Fourteen atoms: SHA-256 of proposal bytes, nonce, A identity, A location, B identity, B location, prior tip, result tip, new revision decimal, numerator A, numerator B, denominator, synthetic, local-fixture-permit. Full journal is returned separately (bounded by XPO-005). Python checker takes original proposal and prior journal independently retained by caller, not solely supplied by the executor.

## Boundaries

The existing permit signs execution scope and exact journal inputs, NOT proposal bytes, location strings or returned receipts. Fixed host mappings and adapter comparison link them in this fixture. A result capsule digest is integrity only, not authentication. Python verifies mathematical replay, proposal/result linkage and exact history extension, not the Ed25519 signature or real execution provenance; it reports that boundary explicitly. A fabricated mathematically consistent history cannot establish external execution. Signer and gate use ephemeral test keys and local process memory. Rollback/restart weakness remains. No arbitrary operations, general graph routing, durable transactions or production access control. The adapter assumes a trusted in-process gate and fixed configuration. Trusted fixture subprocess bridge is not a public input API.

## Reproduce

Node 20+, Python 3.10+, no third-party packages: node tests/interop-conformance.mjs. 36 Python-produced proposals, JS admission and execution, Python independent verification of every return. Refusals cover identity/location, concept/unit/unknown, non-grid weights, stale history, altered nonce, malformed transport, mismatched signed operation weight, invalid signature, replay, incorrect result, prior-history substitution and exhausted capacity.
